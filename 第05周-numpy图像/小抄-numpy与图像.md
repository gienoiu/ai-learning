## 一、图像到底是什么

一张彩色图片 = 一个三维数组：

```text
shape = (高, 宽, 3)
        240, 320, 3        ← 240 行、320 列、每个像素 3 个数（R, G, B）
```

- 每个数字范围 **0~255**，类型 `uint8`（无符号 8 位整数）
- `0` = 全黑，`255` = 最亮
- 红绿蓝三个通道叠加，就出现各种颜色

```python
from PIL import Image
import numpy as np

img = np.array(Image.open("示例图片.png"))
print(img.shape)   # (240, 320, 3)
print(img.dtype)   # uint8
print(img[0, 0])   # 左上角那个像素的 [R, G, B]
```

## 二、numpy 的几个核心操作

### 形状 shape

```python
img.shape          # (240, 320, 3)
img.shape[0]       # 240  高（行数）
img.shape[1]       # 320  宽（列数）
img.shape[2]       # 3    颜色通道数
```

### 索引：取一个像素

```python
img[0, 0]          # 第 0 行、第 0 列 那个像素的 RGB
img[100, 50]       # 第 100 行、第 50 列
```

⚠️ **顺序是 [行, 列]，也就是 [y, x]**，先上下再左右。这是最容易错的地方。

### 切片：取一块

```python
img[40:200, 80:280]        # 行 40~199、列 80~279 的一块
img[:, ::-1]               # 左右翻转
img[::-1, :]               # 上下翻转
```

- `start:stop` = 从 start 到 stop **之前**（和 range 一样）
- `::-1` = 倒着走，所以是翻转
- 省略（`: `）= 全都要

### 通道：单独取 R/G/B

```python
r = img[:, :, 0]
g = img[:, :, 1]
b = img[:, :, 2]
```

### 变成灰度：三维变二维

```python
gray = 0.299 * r + 0.587 * g + 0.114 * b
print(gray.shape)   # (240, 320)，少了一维
gray = gray.astype("uint8")   # 保存前转回整数
```

### 保存图片

```python
from PIL import Image
Image.fromarray(gray).save("输出/变灰.png")
```

## 三、三个任务的思路（不给代码）

| 任务 | 思路 |
|---|---|
| 变灰 | 拆出 R/G/B 三个通道 → 按权重相加 → 得到二维数组 → 保存 |
| 翻转 | 二维/三维数组都能翻：行倒序是 `[::-1]`，列倒序是 `[:, ::-1]` |
| 裁剪 | 切片 `[行起点:行终点, 列起点:列终点]` |

## 四、常见坑

| 现象 | 原因 |
|---|---|
| 图片保存出来全黑/全白 | 数值算出来是 0~1 的小数，但保存时按 0~255 解释；或忘了转 `uint8` |
| 翻转后方向不对 | 行和列搞反了：`[::-1]` 是上下翻，`[:, ::-1]` 是左右翻 |
| `IndexError` | 切片的行/列超出 `shape` 范围 |
| 灰度图像显示成彩色 | 二维数组保存没问题；显示时有些软件按调色板解释，正常 |
| 数值溢出 | `uint8` 相加会回绕（255+1=0），需要先转 `int` 再转回 |

## 五、自检：这三个 shape 分别是什么

| 表达式 | shape |
|---|---|
| `img` | (240, 320, 3) |
| `img[::-1]` | (240, 320, 3)（只是内容翻转，形状不变） |
| `img[:, :, 0]` | (240, 320) |
| `img[40:200, 80:280]` | (160, 200, 3) |
